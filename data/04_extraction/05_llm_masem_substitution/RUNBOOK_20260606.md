## Clean-shard rule

A shard is clean only if all are true:

- The run CSV has the expected row count.
- `error_code` has no `model_cli_error`.
- The file is listed in the locked-output manifest with
  `locked_status=locked_model_output`.
- `score_locked_outputs.py` runs successfully after registration.

If a shard contains session-limit rows, remove its manifest row and rerun it
after the provider limit resets. The failed CSV can remain on disk, but it must
not be in the manifest.

## Why previous runs used many tokens

The expensive parts were not the model CSV rows themselves. The token-heavy
parts were frequent progress narration, repeated full command output, repeated
manifest and score-summary dumps, and documenting every recovery step in chat.
For future continuations, keep command output summarized and write durable
details into files instead of the chat transcript.
